## Ficou de fora (e por quê)

- **Instalação do gitleaks pela release oficial do GitHub.** O prompt pedia
  o binário da release do GitHub em `/usr/local/bin`; a rede desta sessão só
  libera `registry.npmjs.org` (e, por tabela, `proxy.golang.org`, que também
  está na lista padrão de exceções). `github.com` e `api.github.com`
  devolveram 400/403 na tentativa de baixar o binário direto. Instalei o
  gitleaks com `go install github.com/zricethezav/gitleaks/v8@latest`
  (fonte oficial do mesmo projeto, servida pelo proxy de módulos Go), que
  compilou o binário no mesmo caminho (`/usr/local/bin/gitleaks`), versão
  v8.30.1. Funcionalmente equivalente; só o caminho de instalação difere do
  pedido. Se a rede do ambiente de CI ou de outra sessão permitir
  `github.com`, o binário oficial pode substituir este sem mudar nada no
  projeto.
- **CLI do shadcn/ui.** Pelo mesmo motivo de rede (o `init` chama
  `ui.shadcn.com`), a inicialização foi feita à mão. O resultado
  (`components.json`, `src/lib/utils.ts`, variáveis CSS) é o que o CLI
  geraria com `--base radix --css-variables`; só não passou pelo comando.
- **Paleta de marca e componentes de `src/components/ui`.** De propósito
  fora do P00 ("sem design ainda" no prompt). `src/app/globals.css` só tem o
  baseline neutro do shadcn; a paleta de `CLAUDE.md` e de
  `docs/design/DESIGN.md` entra no P10.
- **Teste de "nenhuma cor em hexadecimal fora de globals.css".** É item 6 do
  P10, não do P00. Hoje a checagem é manual (só `globals.css` tem cor).
- **Branches `hml` e `main` protegidas.** É item do checklist humano (P-1,
  item 1: organização, colaboradores e proteção de branch no GitHub) e não é
  tarefa do Claude Code. O workflow de CI já mira PR e push para as duas.
- **`pnpm dev` como parte da verificação.** Não é um dos comandos do item 8
  do prompt (que pede lint, typecheck, test, build e e2e); não rodei
  servidor de desenvolvimento como parte do aceite.

## Decisões tomadas nesta sessão

- **Duas configurações de Playwright**, não dois projetos na mesma
  configuração: `playwright.config.ts` (celular e computador, smoke test da
  home) e `playwright.offline.config.ts` (invariante 4, hoje só com um
  placeholder). Motivo: o invariante 4 precisa desligar a rede a meio do
  teste, o que pede um fluxo diferente do smoke test comum, e `e2e:offline`
  tinha que existir e passar sem teste real ainda.
- **Layout raiz sem `LayoutProps<"/">.`** O Next.js 16 gera esse tipo em
  `.next/types` só depois de um build ou `next dev`. Usar esse tipo faria o
  `pnpm typecheck` falhar num checkout limpo, antes do primeiro build (o job
  `typecheck` da CI roda em paralelo ao `build`, sem depender dele). Troquei
  por `{ children: ReactNode }`, mais portátil.
- **`.gitleaks.toml` na raiz**, com allowlist só dos caminhos que o
  `.gitignore` já exclui (`.next/`, `node_modules/`, relatórios de teste
  etc.). Sem ele, `gitleaks detect --no-git` (que varre o disco, não o git)
  acusava quatro "segredos" que eram só chaves de cache de build do
  Next.js, geradas de novo a cada `pnpm build` e nunca versionadas. Isso é
  independente da CI: `gitleaks-action` varre o histórico do git, que nunca
  teve `.next/`.
- **`.prettierignore` cobrindo os arquivos e pastas fora do escopo desta
  sessão** (`CLAUDE.md`, `PRD.md`, `PROMPTS.md`, `docs/analise-*.md`,
  `docs/referencia-materiais-clinicos.md`, `docs/aprovacao/`,
  `docs/design/`, `n8n/prompts/`, `n8n/referencia/`, `docs/prototipo/`).
  Sem isso, `pnpm format`/`prettier --check .` reformata esses arquivos por
  padrão. Isso realmente aconteceu uma vez durante a sessão (rodei
  `pnpm format` antes de excluir esses caminhos) e o `git checkout --` das
  entregas reverteu na hora, antes de qualquer commit; a lista no
  `.prettierignore` evita que se repita.
- **`eslint.config.mjs` ignora `docs/prototipo/`, `n8n/dist/` e as pastas de
  relatório**, pelo mesmo motivo: nada gerado ou de outra sessão deveria
  entrar no lint deste projeto Next.js.

## Como testar

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build

# Playwright: se o navegador não estiver no cache padrão do Playwright,
# aponte para o Chromium já instalado no ambiente:
PW_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium pnpm e2e
PW_CHROMIUM_EXECUTABLE=/opt/pw-browsers/chromium pnpm e2e:offline

# gitleaks (usa .gitleaks.toml da raiz automaticamente):
gitleaks detect --no-git --no-banner
```
