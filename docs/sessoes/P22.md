## Decisões tomadas nesta sessão

- Aviso ao grupo em rascunho sai mesmo assim, marcado
  `mensagem_grupo_aprovada: false` (saúde e perda sempre chegam à
  coordenação); texto para a família e instrução ao agente só aprovados.
- `humano_comercial` pelo texto do PRD: `reuniao`, `contratar` e
  `condicao_comercial` sempre, e qualquer transferência ao comercial com a
  oportunidade em `qualificado` ou adiante.
- Se o freio ou a família mínima falharem, a transferência e o aviso ao
  grupo saem mesmo assim, com aviso no retorno.
- Sem `handoff_dedup_minutos`, nada é deduplicado (falha para o lado de
  avisar).
- Família mínima só para lead, cliente ou conversa não classificada, e
  sempre para saúde, perda, estado sensível e áudio não transcrito.
- `eliminar_titular` também apaga as famílias mescladas na eliminada, limpa
  o texto livre comercial, marca `nao_contatar` e cancela execuções
  agendadas.
- `privado.agendar_followup_d1` (0012) redefinido para deduplicar por
  qualquer status.
- Caso-limite conhecido: duas transferências na mesma execução, uma com
  pausa e outra que põe a conversa em `humano_comercial`, bloqueiam a
  resposta do modelo (falha para o lado seguro).

## Como testar

Sem Docker (esta máquina), na raiz do repositório:

```bash
cd supabase/sem-docker
PGPORT=54342 PGDATA=/tmp/kz-pg-final scripts/iniciar.sh    # sobe o Postgres 16 local (idempotente)
PGPORT=54342 PGDATA=/tmp/kz-pg-final scripts/testar.sh     # reset do zero + seeds do config.toml + pg_prove
PGPORT=54342 PGDATA=/tmp/kz-pg-final scripts/parar.sh
cd ../..
node supabase/checar-seed.mjs
```

Um arquivo só, depois de um `scripts/resetar.sh` (o `000_harness.sql` cria o
schema `testes` que os outros usam):

```bash
sudo -u postgres pg_prove --host 127.0.0.1 --port 54342 --dbname kraamzorg --username postgres \
  supabase/tests/000_harness.sql supabase/tests/ARQUIVO.sql
```

Com Docker (prova final antes de qualquer `db push`, `supabase/LIGAR.md`):

```bash
supabase start
supabase db reset     # migrations + [db.seed] de supabase/config.toml
supabase test db
```
