## Ficou de fora (e por quê)

- Wrapper do app (`api.transicionar`): P07.
- Menu "Mover para" do app: `api.transicoes_permitidas(maquina, de)` chegou
  na integração (`0015_crm_apoio.sql`, ver P07.md), porque
  `privado.transicao_permitida` não é legível pelo app.

## Decisões tomadas nesta sessão

- Diretoria substitui qualquer papel, menos saindo de `intercorrencia`
  (PRD 7.2: só coordenação). Coordenação cobre as transições de enfermeira
  (PRD 13: agenda e registro Total).
- Pausas (`intercorrencia`, `suspenso`) só voltam para o estado anterior,
  lido da linha do tempo; sair de `intercorrencia` exige motivo.
- Chamada sem usuário (automação, webhook, agente) só faz transição
  automática; requisição `anon` ou `authenticated` sem `sub` nunca conta
  como sistema.
- O gatilho confere a marca exata (`maquina:entidade:destino`) e que o
  update roda como dono: um papel do app que forje `app.transicao` continua
  recusado.

## Como testar

Sem Docker (esta máquina), na raiz do repositório:

```bash
cd supabase/sem-docker
PGPORT=54342 PGDATA=/tmp/kz-pg-final scripts/iniciar.sh    # sobe o Postgres 16 local (idempotente)
PGPORT=54342 PGDATA=/tmp/kz-pg-final scripts/testar.sh     # reset do zero + seeds do config.toml + pg_prove
PGPORT=54342 PGDATA=/tmp/kz-pg-final scripts/parar.sh
cd ../..
node supabase/checar-seed.mjs
```

Um arquivo só, depois de um `scripts/resetar.sh` (o `000_harness.sql` cria o
schema `testes` que os outros usam):

```bash
sudo -u postgres pg_prove --host 127.0.0.1 --port 54342 --dbname kraamzorg --username postgres \
  supabase/tests/000_harness.sql supabase/tests/ARQUIVO.sql
```

Com Docker (prova final antes de qualquer `db push`, `supabase/LIGAR.md`):

```bash
supabase start
supabase db reset     # migrations + [db.seed] de supabase/config.toml
supabase test db
```
