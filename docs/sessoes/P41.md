### Achado de terceiro e correção: fonte do PDF

`@react-pdf/renderer` usa `pdfkit`/`fontkit@2.0.4`, e a versão instalada desse `fontkit` reconstrói errado a tabela `glyf`/`loca` de uma fonte `.woff2` assim que o PDF usa mais de oito glifos distintos de uma família (qualquer frase normal passa disso), e derruba a geração com `RangeError: Offset is outside the bounds of the DataView`. Reproduzido isolado com a string `"abcdefghi"` (nove letras, sem acento nem símbolo) na mesma fonte Inter que a interface já usa. Não é bug deste projeto; é da combinação `fontkit@2.0.4` (a mais nova publicada) com o `.woff2` gerado pelo google-webfonts-helper.

Correção: `scripts/gerar-fontes-pdf.py` reempacota o mesmo Jost/Inter/IBM Plex Mono de `src/app/fonts` (mesmo glifo, mesma métrica, `fonttools`, `flavor = None`) em `.ttf` puro, salvos em `src/lib/pdf/fontes-arquivos/`. O `.ttf` não passa pela reconstrução do woff2 dentro do `fontkit` e não bate no bug (testado com acento, símbolo (`°C`, `SpO2`) e texto longo). A interface continua com os `.woff2` de sempre; só o PDF, que roda fora do navegador, precisa do outro contêiner. O script precisa de `fonttools` (`pip install fonttools brotli`), só para rodar de novo se a fonte mudar; o app e o build do Next não dependem de Python em nenhum outro lugar.

## Como testar

```sh
cd src/lib/pdf
pnpm vitest run src/lib/pdf        # 6 arquivos, 55 testes: curva de peso, textos, validações, metadados, tokens e a geração fim a fim
pnpm lint
pnpm typecheck
```

`gerar.test.ts` é o roteiro do aceite: monta um acompanhamento sintético completo (`Família Teste Aurora`, no padrão de `supabase/seed.sql`) e prova as três frases do aceite do prompt:
- gera os PDFs certos (`gerarEvolucaoPuerperal`/`gerarEvolucaoNeonatal` devolvem `ok: true`, o buffer começa com `%PDF-` e o nome do arquivo é `{id}.pdf`);
- conclusão incoerente bloqueia: ganho "progressivo" com curva de perda, aleitamento "exclusivo" com complemento registrado e conclusão "sem icterícia" com icterícia registrada devolvem `ok: false` com a lista de erros, sem gerar PDF nenhum;
- metadados sem nome: `/Title` e `/Author` do PDF gerado (lidos direto do binário, inclusive o caso em que o pdfkit grava o título em UTF-16BE por causa do acento) são o título genérico do tipo de documento e "Kraamzorg Brasil", nunca "Marina" nem "Aurora".
